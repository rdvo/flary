Flary separates tool description from tool execution. The model sees a small
gateway. It searches or describes a tool, then Flary validates the arguments,
checks the active mode, resolves secrets, and executes the tool in trusted
host code.

## Define a native tool

Use `app.fn()` for application tools. Give the function a stable name, Zod
input and output schemas, and a policy.

```ts
import { flary, z } from "flary";

const app = flary({ name: "support" });

export const getOrder = app.fn({
  name: "orders.get",
  description: "Read one order from the product database.",
  input: z.object({ orderId: z.string().min(1) }),
  output: z.object({ id: z.string(), status: z.string() }),
  policy: {
    operation: "read",
    capabilities: ["orders.read"],
  },
  run: ({ orderId }, { bindings }) =>
    bindings.orders.read(orderId),
});
```

The input and output schemas run in trusted code. The model receives schema
metadata, not the executable closure or secret value.

## Require approval for writes

```ts
export const refund = app.fn({
  name: "billing.refund",
  description: "Issue a refund for one order.",
  input: z.object({
    orderId: z.string(),
    amountCents: z.number().int().positive(),
  }),
  output: z.object({ refundId: z.string() }),
  policy: {
    operation: "write",
    capabilities: ["billing.refund"],
    requiresApproval: true,
  },
  run: ({ orderId, amountCents }, { bindings }) =>
    bindings.billing.refund(orderId, amountCents),
});
```

Writes require an idempotency key. A mode or approval policy can add another
gate. An approval is bound to the exact run, tool, arguments, resource, mode,
and credential generation.

## Build a lazy registry

```ts
const tools = app.tools({ getOrder, refund });

export const support = app.fn({
  input: z.object({ question: z.string().min(1) }),
  output: z.object({ answer: z.string() }),
  tools,
  prompt: ({ question }) => question,
});
```

The gateway exposes four operations:

| Gateway tool | Purpose |
| --- | --- |
| tool_search | Find short redacted summaries by name, tag, or capability |
| tool_describe | Load one selected input schema |
| tool_call | Execute one validated call |
| tool_batch | Execute a dependency-aware batch |

Tool schemas load only after search or describe. This keeps a large tool
library out of every model request.

## Parallel calls

Flary can run independent read calls concurrently. It serializes writes by
resource key and uses the tool journal for idempotency. Code Mode may use
`Promise.all` only for operations marked independent.

```ts
const report = await runtime.batch({
  calls: [
    { id: "orders.get", arguments: { orderId: "order_1" } },
    { id: "orders.get", arguments: { orderId: "order_2" } },
  ],
});
```

Do not parallelize two calls that can mutate the same resource or connection.

## Connect remote MCP

The host product owns connection records, OAuth or API-key setup, encrypted
credentials, organization grants, and the endpoints enabled for a thread.
Register the source in the function definition:

```ts
const external = app.tools({
  github: app.mcp({
    namespace: "github",
    connection: "github-production",
  }),
  billing: app.openapi({
    namespace: "billing",
    spec: "./openapi/billing.yaml",
    connection: "billing-api",
  }),
});
```

For example, connect
[GitHub's read-only remote MCP server](https://github.com/github/github-mcp-server/blob/main/docs/remote-server.md)
with a fine-grained personal access token. Store the token as a Worker secret:

```bash
npx wrangler secret put GITHUB_MCP_PAT
```

Add the secret binding and credential resolver to the application:

```ts
import { createMcpConnection, flary, z } from "flary";

export const app = flary({
  model: "openai/gpt-5",
  bindings: z.object({
    OPENAI_API_KEY: z.string().min(1),
    GITHUB_MCP_PAT: z.string().min(1),
  }),
  auth: authenticateProductRequest,
  resolveMcp: (source, { bindings }) => {
    if (source.connection !== "github") {
      throw new Error("The MCP connection is not approved");
    }
    return createMcpConnection(source, {
      credentials: {
        get: async () => ({
          kind: "bearer",
          value: bindings.GITHUB_MCP_PAT,
        }),
      },
    });
  },
});
```

Register the endpoint in the tool registry:

```ts
const github = app.mcp({
  namespace: "github",
  connection: "github",
  url: "https://api.githubcopilot.com/mcp/readonly",
});

export const tools = app.tools({ github });
```

The endpoint is GitHub's hosted read-only MCP route. Give the PAT only the
repository access that the function needs. The credential callback runs in
trusted host code during discovery and invocation; the PAT does not enter the
model prompt or public tool metadata.

Resolve the sources in trusted host code. Flary's low-level adapter is
available when the host needs explicit storage, caching, and event hooks:

```ts
import {
  SqliteMcpDescriptorCache,
  SqliteToolExecutionJournal,
} from "flary/cloudflare";
import { createMcpTools } from "flary/mcp";

const tools = await createMcpTools({
  scope: trusted,
  endpoints: await productConnections.mcpEndpoints(trusted),
  credentials: ({ endpoint }) =>
    productConnections.resolveCredential(endpoint.connectionId),
  permissions: ({ endpoint, tool }) =>
    productConnections.canUseTool(trusted, endpoint.connectionId, tool.name),
  mode,
  runId,
  descriptorCache: new SqliteMcpDescriptorCache(threadSql),
  journal: new SqliteToolExecutionJournal(threadSql),
  approve: approvals.require,
  onEvent: (event) => threadEvents.append(event),
});
```

Credential callbacks run only in trusted host code. Credential values do not
enter tool descriptions, model input, logs, or normalized events.

Remote HTTP and SSE endpoints must use HTTPS. The adapter validates redirects,
blocks private-network destinations, caps descriptor and schema sizes, and
isolates endpoint failures. Stdio is for self-hosted deployments only.

## Tool safety rules

- Give every tool a stable name and capability.
- Use `read` for reads and `write` for mutations.
- Give writes a resource key and idempotency key.
- Require approval for deletes, external messages, secrets, commits, merges,
  deploys, and other irreversible effects.
- Resolve credentials only for the duration of a protected callback.
- Keep MCP connections scoped to the authenticated tenant and thread.
- Treat `outcome_unknown` as a reconciliation task. Never blindly retry it.
