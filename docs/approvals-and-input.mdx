---
title: Approvals and user input
description: Pause durable work for a decision or missing information and resume safely.
section: Run
order: 2
---

Approvals protect a known action. User input supplies information that the
agent cannot safely infer. Both are durable thread records.

A write that requires approval pauses before the trusted host executes it. The
client can list pending approvals and approve or reject one request. After
approval, completed earlier calls replay from the journal and the approved
write receives a stable idempotency key.

```ts
for await (const event of thread.stream()) {
  if (event.type === "approval.requested") {
    await thread.approve({ approvalId: event.approvalId });
  }
}
```

A write that started but has no terminal record becomes `outcome_unknown`.
Flary does not run it again automatically.

Requested input uses the same restart-safe pattern:

```ts
await thread.sendInput({
  requestId,
  answers: { environment: "staging" },
});
```

Every approval and input request is tenant-scoped, audited, and available after
reconnect.
