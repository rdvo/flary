This example defines one typed support function and exposes it behind a
product-owned API. The product still owns login, organization roles, billing,
connections, and the chat UI.

## Define the app and tool

```ts
// src/flary.ts
import { flary, z } from "flary";

export const app = flary<Env>({
  name: "support",
  model: "anthropic/claude-sonnet-4-5",
  bindings: z.object({
    ANTHROPIC_API_KEY: z.string().min(1),
    APP_ENV: z.string(),
  }),
  auth: async ({ request, bindings }) => {
    const caller = await authenticateProductRequest(request, bindings);
    return {
      tenantId: caller.tenantId,
      userId: caller.userId,
      applicationId: "support-console",
      roles: caller.roles,
      scopes: caller.scopes,
    };
  },
});
```

```ts
// src/tools.ts
import { z } from "flary";
import { app } from "./flary";

const searchDocs = app.fn({
  name: "docs.search",
  description: "Search approved product documentation.",
  input: z.object({ query: z.string().min(1) }),
  output: z.array(z.object({
    title: z.string(),
    excerpt: z.string(),
    url: z.string().url(),
  })),
  policy: { operation: "read", capabilities: ["docs.read"] },
  run: async ({ query }) => docs.search(query),
});

export const tools = app.tools({ searchDocs });
```

## Define the function

```ts
// src/support.ts
import { z } from "flary";
import { app } from "./flary";
import { tools } from "./tools";

export const support = app.fn({
  input: z.object({
    customer: z.object({ name: z.string().min(1) }),
    question: z.string().min(1),
  }),
  output: z.object({
    answer: z.string(),
    sources: z.array(z.string().url()),
  }),
  tools,
  mode: "build",
  thinking: "medium",
  prompt: ({ customer, question }) => [
    "Resolve the support request with approved tools.",
    "Ask before changing customer data.",
    `Customer: ${customer.name}`,
    `Question: ${question}`,
  ].join("\n"),
});
```

The model sees one `execute` tool. Code Mode searches the private tool catalog,
loads only the selected schema, and calls the native tool in trusted host code.
The tool policy and active mode are checked before execution.

## Serve the function

```ts
import { app } from "./flary";
import { support } from "./support";

export default app.serve({ support });
```

This exposes:

- `POST /functions/support` for a direct call.
- `POST /functions/support/runs` for a durable run.
- `GET /functions/support/runs/:runId` for status and output.
- Approval, user-input, and cancellation routes under the same run.

For Cloudflare bindings and a Flue-backed run service, see
[Self-hosting](/docs/self-hosting/). The function definition does not change.

## Connect the product UI

```ts
import { flary } from "flary/client";
import type { support } from "./support";

const client = flary<{ support: typeof support }>({
  baseUrl: "https://support.example.com",
  headers: () => ({ authorization: `Bearer ${sessionToken()}` }),
});

const run = await client.support.start(
  {
    customer: { name: "Ada" },
    question: "How do I change my plan?",
  },
  { idempotencyKey: "ticket_42:turn:7" },
);

for await (const event of run.stream()) {
  renderSupportEvent(event);
}
```

The run ID is stable across a browser disconnect. The client can reconnect to
the same run. For exact event cursors and low-level route control, use the
reference API in [Durable threads](/docs/durable-threads/).
