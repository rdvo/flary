Use `app.agent()` for a coding session that must behave like a persistent
development agent. The thread keeps one canonical transcript, one workspace,
provider pins for each turn, approvals, audits, child agents, and checkpoint
history.

Use `app.fn()` when the work has a finite input and output and does not need an
interactive thread.

## Define the application

~~~ts
// src/flary.ts
import { flary } from "flary";

export const app = flary({
  name: "coding-agent",
  model: "anthropic/claude-sonnet",
  auth: async ({ request }) => {
    const user = await authenticateDeveloper(request);
    return {
      tenantId: user.organizationId,
      userId: user.id,
      roles: user.roles,
    };
  },
});
~~~

The application owns authentication. Provider credentials stay in Worker
secrets or trusted connection resolvers. They do not enter prompts or tool
arguments.

## Register the tool sources

~~~ts
// src/tools.ts
import { z } from "flary";
import { app } from "./flary";

const searchDocs = app.fn({
  description: "Search approved project documentation.",
  input: z.object({ query: z.string().min(1) }),
  output: z.array(z.object({
    title: z.string(),
    url: z.string().url(),
    excerpt: z.string(),
  })),
  policy: { operation: "read", capabilities: ["docs.read"] },
  run: ({ query }) => docs.search(query),
});

const github = app.mcp("github");

export const codingTools = app.tools({
  searchDocs,
  github,
  workspace: app.workspace({ branch: "run" }),
  shell: app.sandbox({
    network: "restricted",
    sleepAfter: "10m",
  }),
});
~~~

`app.workspace()` uses the generated branch-scoped Workspace Durable Object.
It provides file and Git operations through the lazy catalog. `app.sandbox()`
is separate and runs builds or long processes when the host has a Sandbox
binding.

## Declare cross-provider agents

~~~ts
// src/agents.ts
import { app } from "./flary";
import { codingTools } from "./tools";

export const reviewer = app.agent({
  name: "reviewer",
  model: "openai/gpt-5.6-sol",
  models: { allow: ["openai/gpt-5.6-sol"] },
  instructions: [
    "Inspect the current workspace diff.",
    "Run focused checks and report concrete defects.",
  ].join("\n"),
  mode: "review",
  tools: codingTools,
});

export const coder = app.agent({
  name: "coder",
  model: "anthropic/claude-sonnet",
  models: {
    allow: ["anthropic/claude-sonnet", "openai/gpt-5.6-sol"],
    switching: "user",
    fallback: "none",
  },
  instructions: [
    "Inspect the repository before making changes.",
    "Implement the request, run checks, review the diff, and report the result.",
    "Delegate focused review work when it improves the result.",
  ].join("\n"),
  thinking: "high",
  mode: "build",
  tools: codingTools,
  subagents: { reviewer },
  delegation: {
    mode: "auto",
    maxConcurrent: 4,
    maxTotal: 16,
    maxDepth: 2,
    allowPeerMessaging: true,
  },
  compaction: { mode: "auto" },
  limits: { steps: 200, toolCalls: 500, costUsd: 20 },
});

export const functions = { coder, reviewer };
~~~

The Anthropic parent can start the OpenAI reviewer. Each child gets a separate
durable transcript, model pin, approval state, audit view, usage record, and
mailbox. The child shares the parent workspace unless the application creates
an isolated workspace.

## Serve the complete API

~~~ts
// src/index.ts
import { app } from "./flary";
import { functions } from "./agents";

export default app.serve(functions);
~~~

No handwritten Hono routes are required. The Vite integration generates the
Flue, Thread Control, Runtime, and Workspace Durable Object bindings, plus the
D1 catalog, projection Queue, and R2 bindings.

## Create and reconnect to a thread

~~~ts
import { flary } from "flary/client";
import type { functions } from "../worker/src/agents";

const api = flary<typeof functions>({
  baseUrl: "https://agent.example.com",
  headers: () => ({
    authorization: `Bearer ${sessionToken()}`,
  }),
});

const thread = await api.coder.threads.create({
  workspace: {
    organizationId: "acme",
    appId: "coder",
    projectId: "api",
    workspaceId: "main",
    branch: "main",
  },
  mode: "build",
  thinkingLevel: "high",
});

await thread.send({
  message: "Add rate limits to the public API and run the tests.",
  mode: "queue",
});

for await (const event of thread.stream()) {
  renderAgentEvent(event);
}
~~~

Store `thread.ref.threadId` and the newest stream cursor in the product. A web
UI, CLI, Telegram bot, or Discord bot can reopen the same thread later:

~~~ts
const sameThread = await api.coder.threads.open({
  organizationId: "acme",
  threadId: savedThreadId,
});

await sameThread.send({ message: "Continue from the current workspace." });
~~~

The client does not resend the complete transcript. Flue reconstructs context
from the canonical durable thread. A one-turn model override or a persistent
model change keeps the same thread and workspace:

~~~ts
await sameThread.model.set("openai/gpt-5.6-sol");
await sameThread.send({ message: "Continue with the OpenAI model." });

await sameThread.send({
  message: "Ask the Anthropic model to review this turn.",
  model: "anthropic/claude-sonnet",
});
~~~

## Subagents and workspace checkpoints

The model can start declared children through its coordination tools. The UI
can use the same durable controls:

~~~ts
const child = await sameThread.subagents.spawn({
  agent: "reviewer",
  task: "Review the current diff and run focused tests.",
  model: "openai/gpt-5.6-sol",
  seedTurns: 2,
});

await sameThread.subagents.send({
  toThreadId: child.thread.threadId,
  content: "Also check the database migration.",
  mode: "queue",
});

await sameThread.subagents.wait({
  threadIds: [child.thread.threadId],
  timeoutMs: 30_000,
});
~~~

Every completed turn creates an immutable workspace checkpoint. Checkpoints do
not replace Git commits; they let the product show exact turn diffs and restore
the files that existed after a prior turn.

~~~ts
const checkpoints = await sameThread.checkpoints.list();
const diff = await sameThread.checkpoints.diff({
  baseCommitId: "checkpoint_submission_1",
  headCommitId: "checkpoint_submission_2",
});

await sameThread.checkpoints.restore("checkpoint_submission_1");
~~~

Git writes still use policy, approval, journaling, and idempotency controls.
Create a pull request through an approved GitHub MCP or OpenAPI connection
after the branch is pushed.
