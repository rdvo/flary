A coding agent uses the same function runtime as a support bot. The difference
is its workspace, mode, and tool policy.

## Define the app

```ts
// src/flary.ts
import { flary, z } from "flary";

export const app = flary<Env>({
  name: "coding-agent",
  model: "openai/gpt-5.6-codex",
  bindings: z.object({
    OPENAI_API_KEY: z.string().min(1),
    LOADER: z.unknown().optional(),
    WORKSPACE: z.any(),
  }),
  auth: ({ request, bindings }) => authenticateDeveloper(request, bindings),
});
```

## Define workspace tools

```ts
// src/tools.ts
import { z } from "flary";
import { app } from "./flary";

const readFile = app.fn({
  name: "workspace.read_file",
  description: "Read one file from the bound workspace.",
  input: z.object({ path: z.string().min(1) }),
  output: z.object({ path: z.string(), content: z.string() }),
  policy: { operation: "read", capabilities: ["file.read"] },
  run: ({ path }, { bindings }) => bindings.WORKSPACE.read(path),
});

const applyPatch = app.fn({
  name: "workspace.apply_patch",
  description: "Apply one checked patch to the bound branch.",
  input: z.object({ patch: z.string().min(1) }),
  output: z.object({ changedFiles: z.array(z.string()) }),
  policy: {
    operation: "write",
    capabilities: ["file.write"],
    requiresApproval: true,
  },
  run: ({ patch }, { bindings }) => bindings.WORKSPACE.applyPatch(patch),
});

export const tools = app.tools({ readFile, applyPatch });
```

The `run` functions are trusted application code. Their Zod schemas become
lazy tool descriptors. Code Mode exposes a small search/describe/call surface
instead of loading every tool schema into every model request.

## Define the coding function

```ts
// src/coding.ts
import { z } from "flary";
import { app } from "./flary";
import { tools } from "./tools";

export const coding = app.fn({
  input: z.object({ request: z.string().min(1) }),
  output: z.object({
    summary: z.string(),
    changedFiles: z.array(z.string()),
  }),
  mode: "build",
  thinking: "high",
  tools,
  prompt: ({ request }) => [
    "Inspect the bound workspace.",
    "Make small changes, run checks, and report exact files changed.",
    `Task: ${request}`,
  ].join("\n"),
});
```

Build mode can write the bound workspace. The `requiresApproval` policy on
`applyPatch` still pauses the run before the mutation.

## Serve and call it

```ts
// src/index.ts
import { app } from "./flary";
import { coding } from "./coding";

export default app.serve({ coding });
```

Start a durable coding run from the product client with
`client.coding.start({ request })`. The run can pause for approval or user
input and can resume after a disconnect.

The low-level gateway exposes these internal tool operations to Code Mode:

- `tool_search`
- `tool_describe`
- `tool_call`
- `tool_batch`
- `request_user_input`

Independent reads can run in parallel. Writes to the same resource are
serialized and use idempotency keys.

## Add modes

Use `mode: "ask"` or `mode: "plan"` for read-only variants. Use a custom
Zod-backed profile when the coding product needs a narrower capability set.
See [Modes and permissions](/docs/modes-permissions/).
